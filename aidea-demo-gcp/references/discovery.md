# 需求发现与方案选项

根据已有信息选择最短有效路径，不要求固定访谈轮数。

## 先确认云环境与演示路径

在开始需要 Google Cloud 的方案设计前，使用[Google Cloud 环境预检](environment.md)读取一次本机状态。优先复用同一环境中未变化的预检摘要；不因每个方案选项或每轮对话重复调用 CLI。预检只给出 Project 候选和配置迹象，不能搜索用户的全部 Projects，也不能证明 Gemini、BigQuery 或权限可用。

若没有可确认的 GCP Project，方案仍可完整进行：采用**本地模拟 AI 对话 + 固定种子合成数据经营看板**，将真实 Gemini、BigQuery 接入条件作为实施阶段和后续验证路径。不要因此删掉 AI 对话或经营看板，也不要把模拟回答标成真实 Gemini。若发现候选 Project，先在方案中列明目标和真实验证边界，由用户确认之后再决定是否做实际连接。Gemini 与 BigQuery 独立选择，按需给出本地模拟、仅 Gemini、仅 BigQuery、两者均接入四种方案，见[方案设计](solution-design.md)。

## 候选场景

在需求宽泛、目标尚未聚焦且调研资料能支持候选时，提供约 3–5 个差异明确的场景。每个候选包括：业务目标和主要角色；关键业务对象及流程；所需数据或系统；Demo 具体验证什么；重要依赖和取舍。给出一个有依据的建议，并解释理由。

资料不足以支撑结论时，不必先强迫用户提供品牌名或网站 URL；可先给出明确标为假设、待验证的探索方向，并说明每个方向需要哪些资料或证据。不得把这类选项说成客户事实或调研发现。

候选场景可以覆盖不同领域或流程，但不能只更改标题。用户可以选一个、组合多个、修订或提出其他方向。合并后让用户确认优先目标、边界及先后顺序。候选及优先级属于方案建议，用户确认前不等同于客户决定。

## 按决策影响澄清

优先询问会改变流程、数据、系统边界、受众和验收的问题。为容易比较的选择给出适用选项与建议默认。能够从资料验证的事实先调研；客户授权的 CSV/JSON 由 Codex 在生成阶段分析。

把信息保持为三类：

- 已观察或有来源支持的事实。
- 用户明确确认的业务决定。
- 假设、未知及所需的验证证据。

如果剩余未知不阻碍方案，可明示假设并在确认方案中列出；如果未知会改变范围、外部写入、敏感数据或验收标准，先解决关键问题，不启动生成。未回答不视为批准。

方案确认前可以完成只读调研、候选和设计稿；只有确认后的方案才进入 Demo 配置、数据物化和应用生成。
