# 需求与方案设计

## 先判断需求清晰度

- **已有完整方案且确认**：复用既有决定，只检查尚缺的实施信息。
- **业务目标明确、路径未定**：澄清目标用户、业务对象、范围、约束和成功衡量；只问会改变方案的问题。
- **只有客户名、网址或宽泛愿望**：先查可靠资料和网站，整理 3–5 个有依据的候选场景。每个场景简述目标、角色/流程、关键数据、Demo 如何验证、主要依赖及取舍，并推荐一个。让用户选择、组合或修订；组合方案要明确主次与交付顺序。
- **证据不足**：指出不确定处，给出可选择的假设方向；关键范围、目标或真实系统写入条件不能以沉默视作确认。

每轮集中少量高价值问题；能用选择项表达的提供选择项及建议默认。维护确认事实、假设和待核实项，答案确定后不重复提问。候选研究不是结论，行业常见问题不能写成客户事实。

## 方案确认

完整方案至少说明：

1. 业务目标、衡量方式、事实依据、客户确认、假设与未知。
2. 角色、业务对象、端到端流程、交接、完成条件及重要分支。
3. 数据来源、记录粒度、键与关系、规则、质量问题及权威系统。
4. 系统协作、应用体验、领域职责，以及 AI 的输入、输出和边界。
5. 实施阶段、依赖、真实接入条件和后续能力。
6. Demo 验证主张、具体步骤、预期状态、观察点与证据。

面向 ME 售卖方案时，补充建议交付包、客户责任、接入前提和运营服务边界；未核实的商业产品名称、报价、SLA 与效果承诺标为待确认，不把建议包装成已售卖产品。

## Google Cloud 可用性与降级路径

在确认完整方案前读取一次[Google Cloud 环境预检](environment.md)。据此分别设计对话模型和分析数据的实现方式，不要求客户先有 Project 才能继续方案，也不把本地配置检查当成真实 API 验证。

| AI 对话 | 分析数据 | 方案与验证边界 |
|---|---|---|
| 本地模拟 | 合成数据 | 无可确认的 GCP Project 时的默认交付。对话、方案总览、领域操作和经营看板仍完整可演示；问答由确定性本地模拟逻辑提供，合成数据由本地分析代码计算。 |
| 真实 Gemini | 合成数据 | 只在 Vertex AI/Gemini 目标、Project、身份/权限、模型与必要真实场景均确认后采用；看板仍明确标为合成数据。 |
| 本地模拟 | 真实 BigQuery | 只读查询范围、Project、数据集、身份/权限及查询验证均确认后采用；对话明确标为模拟，不宣称模型分析。 |
| 真实 Gemini | 真实 BigQuery | 两个接入分别通过目标确认和必要验证后采用；模型解释、查询结果和确定性指标分别标明来源。 |

把环境状态区分为 `configured/candidate`、`enabled-unverified`、`unknown` 与已由本次目标绑定验证支持的结果。预检只读结果不升级为真实可用；CLI 已登录、ADC 存在、API 已启用、Project 可见都不能单独证明 API 身份、IAM 权限、模型/区域可用性或查询成功。网络和权限错误导致结果不明时保留 `unknown`，不可自动降格成“资源不存在”。

预检得到的 Project 是候选值而非默认客户配置。方案需列明 Gemini 和 BigQuery 分别要用的 Project/区域/模型/数据集/身份/只读范围，客户确认后才进入已授权的验证步骤。环境检查不授权模型调用、查询、创建云资源、启用 API、变更 IAM 或部署。若暂时无 GCP Project，照常确认“本地模拟 + 合成数据”的 Demo 方案，并把上述接入条件保留在完整实施路径；后续项目准备好后再按目标重新确认并验证。

把方案交给用户确认后，才生成应用和场景数据。确认时必须说明是否启用 AI。新V4启用时优先确认split分栏：左侧常驻AI对话、右侧“方案总览”（`solution`）→已确认的业务领域；tabs兼容布局保持chat→solution→业务领域；未启用时不强制显示 AI 智能对话 Tab，方案总览成为首个可见 Tab，并保留按需启用 AI 的能力。确认标题与 Tab 栏固定、内容区独立滚动。业务领域 Tabs 要明确名称、顺序、目标、职责、使用的数据与指标、主要操作、领域间跳转及验收目标。已有确认方案可沿用；实质范围变化才重新确认变化部分。

## Demo 页面设计

split布局中AI对话常驻左侧，右侧首Tab为`solution`方案总览；旧`#tab=chat`展开对话并显示方案总览。tabs兼容布局中首Tab为chat、第二Tab为solution。solution不配置为普通业务页。未启用 AI 时不显示 chat Tab，方案总览为首个可见 Tab。方案总览展示完整方案、流程关系、数据与系统、实施阶段、领域入口和“方案—Demo 对照”，不嵌入聊天。每个对照项映射到真实页面及验收步骤。

AI 智能对话可读取当前 Demo 的已实现领域只读汇总及最新模拟状态。后端请求中的 `domainId=solution` 仅选择只读方案上下文，不代表权限，也不是动作入口；状态修改只能由相应业务领域的页面与处理器校验执行，后续接入资料不能据此升级为已实现。标题和 Tab 栏保持固定，主内容区独立滚动。

其余 Tabs 按客户业务领域拆分。业务名称和数量从已确认流程推导；图表、记录和表单放在领域内，不为每个 Tab 复制聊天面板。AI 智能对话是可选的通用能力：未启用 AI 时不强行添加，但可在后续确认需求后启用。跨领域跳转应传递允许的记录 ID 和上下文，状态修改能在来源领域回读。模拟角色不是认证授权。

### 分层语言、品牌与业务页面

Demo 标题、AI 智能对话、方案总览、分析和说明外壳默认简体中文；客户官网、独立站或产品的实际体验区域按照目标 URL 的已核实语言和客户品牌生成。非中文站点不意味着整套 Demo 都必须翻译；地区、货币和语言是不同维度。调研时记录目标市场、页面语言、品牌素材来源和场景路径，方案确认时明确哪些部分复用客户体验、哪些部分属于方案讲解。按钮、空状态、错误与确认提示也要与所在体验语言一致。

基础组件与确定性业务合同优先复用；页面随客户流程组合。官网优化 Demo 应有可交互的代表性官网路径，而不是只列改版建议或让顾客通过聊天完成所有操作。没有公开资料或授权数据支撑的价格、评价、库存、承诺和经营提升必须保留未知/模拟边界。客户案例只用于回归，不作为下一客户的默认行业、语言或品牌。

领域能力状态：

- `verified`：有可回读证据；不允许仅凭配置声明。
- `simulated`：本地状态和合成数据模拟，清楚标示。
- `unverified`：已实现但尚未验证。
- `planned`：尚未实现的后续接入，不显示可执行操作。

方案完整度可以超过 Demo 范围。没有真实接口时，使用模拟处理结果描述终点；不宣称已发信、创建生产工单、完成购买或提升业绩。

## 方案溯源

客户来源、公开网站观察、推断与假设须明确标注。结论引用可回读的来源 ID；网站记录保留 URL、检查时间、地区与页面观察。完整站点检查流程见 [网站检查](website-review.md)。配置、Playbook 和方案首页共用同一组目标、主张与领域 ID，避免重复维护产生口径漂移。

业务Tab默认优先放置已有的经营看板／分析总览在方案总览右侧，再排列办理、内容或其他业务领域；方案无分析领域时不强加空看板。最终顺序写入已确认pages配置，运行时不猜测业务名称。领域内部的记录／流程切换保持其业务职责，除非用户明确要求提升一级。
